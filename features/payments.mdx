---
title: "Payments and refunds"
description: "Run simulated Sandbox payments or stateless provider checkout."
---

Sandbox accepts a positive integer minor-unit amount and an `Idempotency-Key`. It never contacts a provider and supports `success`, `failure`, `pending`, `insufficient_funds`, `timeout`, and `provider_outage` scenarios.

Production requires an active, validated connection and an `op_live_sk_` key. Select `paystack`, `flutterwave`, or `mono`, send a caller-owned `reference`, and include a transient `contact`. Flutterwave and Mono require `callbackUrl`.

```json
{
  "amount": "50000",
  "currency": "NGN",
  "provider": "paystack",
  "reference": "order_4821",
  "contact": { "email": "buyer@example.com" }
}
```

The response contains a hosted checkout URL. It is not a completed payment. Verify later with `POST /v1/payments/verify` and `{ "provider": "paystack", "reference": "order_4821" }`. OurPocket verifies against the provider and returns the current result without saving it.

Use the provider’s own reference for full or partial refunds. Provider write requests are never retried automatically. Retain provider identifiers and outcomes in your application before initiating support or reconciliation work.
