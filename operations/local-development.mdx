---
title: "Local development"
description: "Run the API, frontend, PostgreSQL, and webhook worker locally."
---

The normalized Sandbox financial API uses PostgreSQL and does not need provider credentials or the older external ledger. Production adapter tests should intercept provider HTTP and avoid real financial transactions.

From `infra/`, install dependencies, configure its `.env` for PostgreSQL and JWT, then apply migrations in timestamp order. The financial migrations are `20260918000000-ProviderCatalog`, `20260919000000-FinancialInfrastructure`, and `20260920000000-FinancialControlPlane`. Use `bun run migration:run` and `bun run start:dev`. The backend exposes Swagger at `/docs`.

Set `PROVIDER_CONFIG_ENCRYPTION_KEY` to a stable secret for encrypted Production connections. Outbound webhook delivery needs Redis (`REDIS_HOST`, `REDIS_PORT`, optional `REDIS_PASSWORD`) and a backend worker with `FINANCIAL_WEBHOOK_WORKER=true`. An API-only process can use `FINANCIAL_WEBHOOK_WORKER=false`. Register webhook destinations with public HTTPS URLs; local/private addresses are rejected even in development.

From `ourpocket/`, run `bun install` and `bun run dev`. Set `VITE_API_BASE_URL` to the backend `/v1` URL if needed. Use the dashboard to register, create a project, and run [the Sandbox quickstart](/quickstart). The TypeScript SDK examples live in `ourpocket/packages/sdk/examples/`.
