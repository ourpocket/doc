---
title: "Current boundaries"
description: "See which parts of the financial control plane execute today."
---

This page describes implemented behavior, not a future roadmap.

- Production payments and refunds use connected Paystack or Flutterwave. Checkout is hosted; initialization does not settle it.
- Production wallet creation uses connected Turnkey or Privy for Ethereum or Solana addresses. It does not provide fiat balances, signing, policy management, on-chain transfers, or a production wallet ledger through the normalized API.
- Sandbox fiat balances, funding, debits, and internal transfers are simulated in PostgreSQL. They do not move real money or use an external ledger.
- Routing evaluates connected payment providers and a saved project policy. Provider status and fee estimates are operator configured; success rate and latency use recent observed operations. Failover only selects a provider before a write. There is no retry or failover after an uncertain provider outcome.
- Reconciliation verifies pending and unknown Production payments and refunds with their original provider. It is not a three-way provider/ledger/bank settlement engine and does not resolve an unknown wallet creation automatically.
- Signed outbound webhooks, retry scheduling, attempt history, test events, and replay exist. They require a running Redis-backed delivery worker. Financial logs expire after seven days.
- Stablecoin infrastructure, KYC/identity, bank payouts, production fiat wallet funding, a native double-entry ledger, executable subscription billing, and enterprise SSO/RBAC are not implemented in these normalized APIs. Catalog visibility is not proof of execution support.
- The TypeScript SDK is private source code in the frontend repository, not a published package. The old Python, Go, and PHP examples target compatibility endpoints.

Use the capability flags from `GET /v1/providers` and the environment-specific dashboard connection state before exposing a feature to customers.
