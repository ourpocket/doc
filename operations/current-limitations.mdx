---
title: "Current limitations"
description: "Understand implemented boundaries before relying on OurPocket in production."
---

This page distinguishes current repository behavior from capabilities that may be planned or implied by the interface.

## Webhooks

- Endpoint registration is implemented.
- The normalized ingress endpoint is implemented.
- Outbound event delivery is not implemented.
- HMAC signing is not implemented.
- Retry queues, delivery attempts, replay, and delivery logs are not implemented.
- Provider-specific signature verification is not implemented.

## Provider routing

- Paystack and Flutterwave are executable routing adapters.
- Routing metrics are supplied by the caller, not calculated from observed usage data.
- Persisted project provider connections are not automatically used by the primary wallet and transaction routes.
- Provider and ledger execution are not atomic.

## Wallets and transactions

- Balances belong to an external ledger not included in this repository.
- Direct wallet credit, debit, and transfer operations do not create local transaction records.
- Unified transaction references are unique, but duplicate requests return a conflict instead of the prior result.
- The API does not define a universal major-unit or minor-unit amount convention across providers.

## Credentials

- Project API keys are encrypted and currently recoverable through backend list operations.
- Webhook secrets are stored but not used for signing.
- The declared Google registration path does not verify a Google identity token.
- The backend permits provider credentials in runtime request bodies.

## Operations

- Redis is provisioned but not used by an active queue or cache.
- Rate-limiting configuration exists, but a global throttling guard was not found.
- CORS allows all origins in application bootstrap.
- Structured request logging, tracing, and dependency health checks are not implemented.

<Warning>
  Complete a security, reconciliation, webhook, and ledger review before using this repository for production financial workloads.
</Warning>
