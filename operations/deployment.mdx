## API image

`infra/Dockerfile` provides development and production stages based on Node.js 20 Alpine. The production stage builds the NestJS application and starts `dist/src/main.js`.

```bash
docker build --target production -t ourpocket-api ./infra
```

## Required services

A deployed API requires:

- PostgreSQL
- External ledger service
- Provider network access
- Email provider when verification and reset email delivery are enabled

Redis is present in configuration and Compose, but the current source does not use it for a queue or cache.

## Database migrations

Run TypeORM migrations as a deployment step before starting new application instances.

```bash
pnpm run migration:run
```

Development uses schema synchronization. Production disables synchronization and depends on migrations.

## Production configuration checklist

- Set `NODE_ENV=production`.
- Use a strong `JWT_SECRET`.
- Set dedicated project-key and provider-configuration encryption secrets.
- Configure a production PostgreSQL URL.
- Configure a reachable and authenticated ledger service.
- Configure `FRONTEND_URL` for email links.
- Configure `RESEND_API_KEY` if email delivery is required.
- Restrict CORS at the deployment boundary.
- Use production provider credentials only with intended live workloads.
- Run migrations before application traffic.
- Add health checks for the API, database, ledger, and providers.

## Current deployment considerations

<Warning>
  The repository does not include the external ledger service, automated migration entrypoint, container health checks, hosted deployment manifest, or outbound webhook worker.
</Warning>

The production database configuration enables SSL with certificate verification disabled. Review this setting for your database provider and security requirements.
