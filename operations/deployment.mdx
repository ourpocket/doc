---
title: "Release order"
description: "Configure the API and worker before exposing the new dashboard."
---

This is an operator note for self-hosted deployments. Back up PostgreSQL and apply the ProviderCatalog, FinancialInfrastructure, and FinancialControlPlane migrations in order. Set a stable `PROVIDER_CONFIG_ENCRYPTION_KEY`; changing it makes existing customer connections unreadable. Run Redis and at least one `FINANCIAL_WEBHOOK_WORKER=true` worker for outbound delivery, then release the backend API before the frontend.

Confirm `/docs`, project creation and one-time Sandbox key delivery, a simulated operation, signed test webhook delivery and replay, and Production provider connection health. Do not route real provider transactions into a Sandbox key. Historical connections with no provable environment need to be reconnected to Production; normalized financial APIs exclude them.

Production chain wallet creation requires customer-owned Turnkey or Privy credentials. Production hosted checkout and refunds require customer-owned Paystack or Flutterwave credentials. The current [boundaries](/operations/current-limitations) distinguish these operations from unimplemented stablecoin, bank payout, native ledger, and enterprise features.
