Provider connections belong to a project and environment. Sandbox runs simulated operations without any provider account. Production reads encrypted connection credentials; operation requests do not accept provider secrets.

| Provider | Implemented Production capability | Required connection fields |
| --- | --- | --- |
| Paystack | Hosted checkout, verification, full/partial refunds | `apiKey` |
| Flutterwave | Hosted checkout, verification, full/partial refunds | `apiKey`, `webhookSecret` |
| Turnkey | Ethereum or Solana chain wallet creation | `organizationId`, `apiPublicKey`, `apiPrivateKey` |
| Privy | Ethereum or Solana chain wallet creation | `appId`, `appSecret` |

Paga, Fincra, Mono, and other catalog entries are not executable financial adapters. Turnkey and Privy do not provide fiat funding or balance transfers through OurPocket. `GET /v1/providers` with a project key returns normalized capability flags; the management catalog is at `GET /v1/provider-catalog` with a user JWT.

## Connect a provider

1. In the dashboard select your project and **Production**, then open **Providers**.
2. Choose an active provider, enter the required account credentials, and save the connection. The dashboard uses `POST /v1/projects/{projectId}/providers/connect` with a catalog `providerId`, `config`, and `X-Environment: production`.
3. Confirm it appears in Production. Connection data is encrypted at rest and secrets are masked in list responses. Saving fields validates their presence, not whether your provider account will accept a live operation.
4. Test a provider-backed operation and inspect the normalized resource and provider response status. Use your provider's own account tools for its separate setup.

Multiple connected payment providers require an explicit `provider` on the payment or a [saved routing policy](/features/routing). There is no automatic financial-write retry. A selected provider's outage can result in an `unknown` operation that needs verification.

The legacy `POST /v1/projects/{projectId}/providers` route only supports Paystack and Flutterwave configuration. Use the catalog connection route for wallet providers.
