---
title: "Supported providers"
description: "Connect a customer-owned provider account and use its live capabilities."
---

Provider connections belong to a project and environment. Sandbox is simulated and never calls external providers. Production requires an active, validated connection and an `op_live_sk_` key.

| Provider | Supported operations |
| --- | --- |
| Paystack | Hosted checkout, verification, refunds, account resolution, recipients, payouts, dedicated accounts, and live overview |
| Flutterwave | Standard checkout, verification, refunds, account resolution, beneficiaries, payouts, virtual accounts, and live overview |
| Mono | DirectPay checkout and verification; connection and capability overview only |

Connect in **Providers** while Production is selected. Credentials are encrypted and masked after saving. Validation checks credentials and accessible products without moving money. Requests never accept provider credentials.

Use `/v1/providers/{provider}/…` with a project key for runtime operations, or `/v1/projects/{projectId}/providers/{provider}/…` with a dashboard JWT for the live overview. A missing product returns `capability_unavailable`; OurPocket never reroutes a write to another provider.

The overview is a fresh, no-cache response. It includes only operational fields and masks account numbers. It retains nothing from the provider response. Keep all provider identifiers and results in your application.
