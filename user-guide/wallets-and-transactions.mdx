title: "Wallets and transactions"

The **Wallets** and **Transactions** screens are interactive request consoles. They help you assemble API inputs, submit an operation, and inspect its immediate response.

<Warning>
  These screens are not wallet inventory or transaction history pages. Do not rely on them to list, retain, or manage all wallets and transactions for a project. Store identifiers and results in your own application when you need durable records or reconciliation.
</Warning>

## Before you send a request

You need:

- A selected project.
- A test or live API key issued for that project.
- An active Paystack or Flutterwave adapter when the operation requires a provider.
- Valid operation inputs, including any required identifiers, currency, amount, reference, credentials, or provider payload.

<Note>
  Selecting a project does not automatically authenticate either console. You must manually paste the project API key into the key field on the screen.
</Note>

## Get the correct API key

When you open **API Keys**, the page checks the selected project and automatically creates a missing test key or live key. It does not require a separate manual generation step for those missing environment keys.

<Steps>
  <Step title="Select the project">
    Open **Projects**, choose **Use Project**, and verify the **Selected** badge.
  </Step>
  <Step title="Open API Keys">
    Navigate to **API Keys**. Allow the page to load and create any missing test or live key for the selected project.
  </Step>
  <Step title="Choose the environment">
    Use the test key for development and non-production requests. Use the live key only for deliberate production activity.
  </Step>
  <Step title="Copy and paste the key">
    Copy the project key and paste it into the API key field in the **Wallets** or **Transactions** console.
  </Step>
</Steps>

<Warning>
  Treat test and live keys as secrets. Do not commit them to source control, expose them in client-side code, or paste them into a console while screen sharing.
</Warning>

## Use the Wallets console

The **Wallets** console exposes forms for wallet operations such as creating a wallet, retrieving a wallet by ID, crediting or debiting a wallet, and transferring value between wallets when those operations are available.

<Steps>
  <Step title="Choose an operation">
    Open **Wallets** and select the operation you want to test.
  </Step>
  <Step title="Authenticate the request">
    Paste the API key for the intended project and environment.
  </Step>
  <Step title="Complete the request fields">
    Enter the identifiers and operation data requested by the form. Where a form accepts JSON, provide syntactically valid JSON with the fields expected by the selected provider.
  </Step>
  <Step title="Submit the operation">
    Review the environment, amount, currency, reference, and wallet identifiers before sending the request.
  </Step>
  <Step title="Record the response">
    Inspect the returned status and identifiers. Copy any values your application needs because the console is not a durable inventory view.
  </Step>
</Steps>

## Use the Transactions console

Use **Transactions** to submit the transaction requests exposed by the screen and inspect their responses. It does not automatically show a project's complete transaction history.

<Steps>
  <Step title="Open Transactions">
    Navigate to the **Transactions** screen with the intended project selected.
  </Step>
  <Step title="Paste the project key">
    Enter the matching test or live API key manually.
  </Step>
  <Step title="Provide transaction inputs">
    Complete the fields required by the selected request. Use a unique reference when the operation accepts one.
  </Step>
  <Step title="Send and inspect">
    Submit the request and review the immediate response for a status, transaction identifier, and error details.
  </Step>
  <Step title="Persist important data">
    Save the request reference, returned identifier, and status in your own system if you need later lookup or reconciliation.
  </Step>
</Steps>

## Interpret transaction states

A response may report one of these transaction states:

- `pending`: the request was accepted, but its outcome is not final.
- `success`: the transaction completed successfully.
- `failed`: the transaction did not complete successfully.

A `pending` response requires application-level follow-up. Do not treat it as a successful transaction.

## Troubleshooting

### The console says the API key is missing

Copy a key from **API Keys** and paste it into the console. Project selection alone does not populate or authorize the request.

### The API key is rejected

Verify that the key belongs to the selected project and that you copied the intended test or live key. Return to **API Keys** after switching projects instead of reusing a key from the previous project.

### A JSON field is invalid

Use valid JSON with double-quoted property names and string values. Remove trailing commas and confirm that the payload matches the selected provider's requirements.

### I cannot find a wallet or transaction list

The screens are request consoles, not inventory or history managers. Use your application's stored identifiers and API integration for durable tracking.

### A provider operation fails

Confirm that Paystack or Flutterwave is configured for the same project, verify the provider credentials and payload, and check that the API key environment matches the intended operation.
