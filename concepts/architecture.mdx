---
title: "Architecture"
description: "How applications, OurPocket, and customer-owned providers interact."
---

Your server calls OurPocket with a project key. The key identifies its Sandbox or Production environment. OurPocket returns normalized resources and events while keeping the provider reference available for inspection.

```text
Your application → OurPocket payments → Paystack / Flutterwave
                 → OurPocket wallets  → Turnkey / Privy
                 ← Signed event webhook
```

In Sandbox, simulated payment and fiat wallet operations use PostgreSQL and do not call providers or the older external ledger. In Production, payment and wallet adapters use encrypted customer-owned connections. Provider responses are normalized; a hosted checkout remains pending until verified. An uncertain provider outcome is recorded as `unknown`, with no automatic financial-write retry.

Events are persisted with state changes and delivered through a Redis-backed worker. The dashboard reads environment-scoped resources, logs, deliveries, routing decisions, and reconciliation runs. See [current boundaries](/operations/current-limitations) for domains that do not yet have normalized execution.
